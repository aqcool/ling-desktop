# 2026-09-28 LING 回归检查

本轮针对现有工作流与 DSH 接入。使用独立 Electron 配置目录、临时 Git 仓库和本地测试模型服务；未使用用户模型凭据，未向用户项目写入 Git 提交。以下区分原生实测、模拟故障与未验收范围。

## 发现并修复

1. 主聊天保存重试函数时，直接将函数传给 React 状态 setter。React 会将其作为 updater 执行，失败后可能自动重发并重复创建任务。现在保存函数本身，只有点击“重试”才再次调用。
2. 网页注释在发送结果返回前被清空。现在通过提交成功回调清理；拒绝、异常和等待过程中保留注释。通知栏重试沿用原始注释内容，成功后同步清除输入框附件与页面标记。

新增可复跑的交互回归 `scripts/check-annotation-retry.mjs`，覆盖浏览器发送与聊天输入框发送两个入口。分别断言：首次失败仅发出一次请求、注释仍存在、手动重试使用相同内容、成功后清空。

## 模拟故障与离线交互

- 侧边多任务切换、独立草稿、折叠后恢复；创建请求尚未结束时折叠，再展开仍接回任务。
- 发送失败保留草稿；审批失败可重试，审批仅影响侧边对应任务。
- 速记创建、编辑、附加、删除、存储恢复；浏览器导航事件去重。
- 网页注释发送拒绝后保留内容，点击重试后清空；验证没有隐式重复请求。

以上使用 demo adapter 和受控故障，证明界面与重试行为；不充当真实模型工具审批的验收结果。

## ChatGPT 登录浏览器补查

用户反馈点击登录按钮没有可见浏览器窗口。原生实测确认 IPC 已调用 `shell.openExternal` 且返回成功，但正常 Chrome 窗口没有授权页；系统中另有此前 `ling-model-settings` Playwright 会话遗留的无窗口 Chrome。关闭该测试会话后，同一个按钮在正常 Chrome 窗口打开了 `auth.openai.com/log-in`。本次修复为清理测试环境，没有更换用户配置目录或修改凭据，也无需替换产品的浏览器接口。

后续浏览器回归必须在退出时关闭自己启动的浏览器和 CLI 会话；不能仅以 `shell.openExternal` 返回成功判断可见浏览器已打开。本次验证止于登录页，账号授权与回调完成仍待用户验证。

用户指出默认浏览器应为 Edge。随后直接查询 macOS `NSWorkspace.urlForApplication(toOpen:)`，HTTP 和 HTTPS 当前均返回 Google Chrome，Edge 安装路径可正常解析。因此只确认了“授权页可见”，尚未确认符合用户预期的默认浏览器。保留系统默认打开行为，不添加浏览器选择，不强制指定浏览器，也不修改系统关联。

## OAuth 令牌兑换与系统代理修复

随后用户完成浏览器授权，后台兑换令牌返回 `unsupported_country_region_territory`。确认 Pi 的成功页在收到授权码时就返回，先于令牌兑换。macOS 已启用静态 HTTP/HTTPS 代理，而 LING Host 仅将环境变量交给 DSH，遗漏了系统代理。

- 宿主启动时以系统静态代理补充缺失的 DSH 代理策略；显式环境变量及用户 `.env` 优先。继续由 DSH 安装请求代理，回环请求保持直连。未修改上游子模块。
- 失败的授权隐藏旧链接与回调输入，允许创建新的登录尝试；地区错误明确显示账号尚未连接。
- 新增 7 项回归，覆盖系统设置、显式配置优先级、绕过列表、不支持的配置、真实 Node fetch 经本地代理以及回环直连。
- 无真实凭据的令牌请求通过系统代理返回 `401 token_expired`，未再出现地区 403；不据此宣称真实账号登录成功。
- 原生 Electron 使用无效测试授权码验证失败后隐藏过期操作、点击“重新登录”产生新流程；未保存测试凭据。Renderer 与 Host 完整检查通过。
