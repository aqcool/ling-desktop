# Qoder 界面还原检查

检查日期：2026-09-26。对象：LING 独立 Electron 宿主与本机 Qoder CN，辅以用户提供的截图。

## 样式修正复查（2026-09-26，后续更新）

按用户要求，后续工作以样式修复为主。以下结果覆盖首轮记录中相应的未通过状态：

- **输入区权限菜单（按最新参考图修正）**：改为 370px 宽的双行菜单，图标 16px、标题 13px 半粗、说明 11.5px、每行至少 50px，完全访问的图标/标题/说明/勾选使用参考图的警告红色。内置 `workspace-write` 显示「询问审批」，说明仍反映 DSH 工作区写入权限；`auto` 修正为「自动审批」，不再误当完全访问。保留运行时提供的只读、自定义预设，不伪造自动审批能力。Playwright 演示实测：宽 370px、4 行各 50px、无滚动溢出，完整截图及菜单局部截图已核对；Renderer 检查通过（253 项测试）。此前单行紧凑菜单方案已替换。

- **归档会话删除入口（仅 UI）**：设置「已归档」每行新增垃圾桶入口及 HeroUI 确认弹窗，保留恢复操作。组件预留异步删除回调、提交中锁定与失败提示；当前 DSH 会话控制器及工作区控制器未提供永久删除会话接口，宿主未传入删除回调，因此确认按钮禁用并说明当前运行时不支持。未删除、隐藏或改写任何真实会话。Renderer 完整检查通过（249 项测试）；本轮未完成实屏验证。

- **统一图标族**：所有操作图标经 `Icon` 输出，使用 24 单位画布、1.75 单位圆头/圆角描边及 `currentColor`；窗口/终端/面板共用外框，文件夹变体共用轮廓，面板开合只改变内部指示块，图标本身不带选中背景或阴影。重画分支、分叉、日历时钟、文档、复制、归档、麦克风、波形、调色盘等轮廓；记忆与钩子使用专属语义图标。尺寸按场景固定：设置/菜单/工具栏内部 16px、主工具栏 18px、入口卡片 20px，折叠箭头与附属标记可使用 12–14px。后续新增图标必须复用此规范，选中容器保持同尺寸居中。

- **会话消息锚点**：在会话滚动区右沿补充按用户轮次排列的短横线；悬停或键盘聚焦时，当前线与相邻线分级伸长，左侧显示 280px 预览卡片（单行标题、至多三行回复摘录）。点击定位原消息，滚动同步当前轮次；系统和工具事件不进入摘录。定位条随会话区域、工作面和底部终端尺寸变化居中，层级低于浮层任务监控。验证：本机 Qoder 对照、演示运行时历史加载/卡片/跳转/工作面与底部终端同时展开、真实 LING「阅读当前项目」跳转与无回复轮次预览；完整 Renderer 检查通过（249 项测试）。

## 首轮结论与范围（修复前）

**目前不能判定整体还原通过。** 框架已有左右分栏、任务监控浮层、底部终端和右侧多标签，但对话内容组织、监控内容语义、模型列表结构与外观设置仍有明显差异。部分入口只有展示，没有对应操作。

此次已修复确认的启动样式过期、Tailwind 状态类冲突及部分尺寸、颜色、图标问题。后端未接入的界面可以保留，这是产品范围内的允许项；但不能把静态界面记录为已实现功能。账户、订阅、充值、折扣、平台倍率等 SaaS 内容不在迁移范围。

本机截图有不同的窗口尺寸与 Retina 比例：LING 截图为 2560 × 1680，对应约 1280 × 840 逻辑像素；Qoder 为 3378 × 1978，对应约 1689 × 989。尺寸比较采用逻辑像素，不能直接拿两张缩放后的截图百分比判断宽窄。

最终一轮重启曾被 Mac 锁屏打断；用户解锁后已继续复查模型、外观、任务监控设置、浅色/深色主界面、右侧文件与浏览器、侧面/底部终端、侧栏按钮折叠和工作面最大化。已确认这批样式实际加载。仍有未通过项及未覆盖状态，以下分别记录。

## 未通过项：优先处理

### P1：影响主要界面组织或让用户误判功能

1. **对话过程仍直接铺满原始系统内容。** `src/ui/Conversation.tsx` 的系统通知直接输出完整文本，包括 AGENTS、技能目录及系统提醒。这与 Qoder 将执行过程折叠、以回复为主的组织方式差异很大，也会把输入区推离用户关注点。应按事件种类组织可折叠过程，保留详情入口；不要依靠 CSS 截断原文。
2. **监控设置与实际内容没有完整对应。** `sideChats`、`memoryUpdates` 有偏好字段和设置开关，监控组件没有读取它们；`demoScreen` 被实现为演示运行时说明，与设置承诺的固定模式演示画面显隐不是同一功能。验收应逐项开关并检查对应区域，不能只检查开关是否保存。
3. **任务回顾和技能列表的数据语义不对。** 回顾取最后一条助手回复，并放在环境信息后；Qoder 实屏有独立回顾卡片。技能列表优先取可用技能目录，并非已使用能力，也没有实际 MCP 使用记录。列表计数已去掉假建议，但仍不能称为任务使用记录。
4. **侧边任务只有静态输入框外观。** `LingShell.tsx` 对 `side-task` 渲染的是普通 `div`，没有输入与发送。多个页签不等于多个可用任务。后端未接入时应显示一致的禁用编辑器，明确状态，不能保留看似可输入的假控件。
5. **侧面与底部终端没有终端数据流。** 宿主 `terminal-projection.ts` 只投影列表和创建，未接入输入、输出、尺寸更新及关闭会话。两处面板开关独立，但不能按真正的独立终端功能验收。
6. **浏览器存在无动作按钮。** “刷新本地服务”和注释编辑器内“调整选择”没有事件处理；首页预置 `localhost:5173`，并非检测到的真实服务。元素选取本身实测可用，这两个动作及本地服务列表仍需修复。
7. **多个右侧页签在侧栏展开后裁切。** 实测复现：收起左侧栏，依次打开终端、浏览器、文件，再展开左侧栏。在当前 1280px 窗口、44% 右侧工作面下，文件页签只剩开头、关闭按钮不可见，横向滚动条占据顶栏；当前页签没有自动滚入可见区域。需在宽度变化和选中变化后保证当前页签可见，并统一标签溢出样式。

### P2：结构、视觉和可用性差异

| 区域 | 仍存在的差异 | 完成标准 |
| --- | --- | --- |
| 模型管理 | LING 按提供商分卡；Qoder 为统一列表。LING 开关表示全局默认选择，Qoder 开关用于模型可用性；两者语义不同 | 先明确展示与动作的对应；统一列表密度；默认模型另有明确标记；不能用同款开关伪装不同行为 |
| 外观设置 | 缺少森林 / 薄荷 / 蜜蜂 / 羊皮纸等主题预览卡；应用图标也只有下拉框。终端主题、字体、宽度多为禁用预览 | 先补齐本地 UI 层的预览结构；禁用不影响尺寸、状态的还原 |
| 对话消息 | 用户消息为深色气泡，角色、时间、状态徽标及错误呈现与 Qoder 不一致 | 在相同任务内容、窗口宽度下核对；长文本、代码、附件和错误分别验收 |
| 顶栏 | Qoder 有运行环境与开发启动入口；LING 仍缺少相应本地 UI | 补齐非 SaaS 入口；没有后端时使用一致的禁用态，不显示虚构运行状态 |
| 侧栏 | Qoder 的编程 / 通用切换在新任务上方；LING 没有相同入口 | 对照模式设置确定完整展示关系，避免只复制设置页 |
| 任务监控 | 固定宽度、回顾卡片、分组顺序、计划入口与操作项仍需细核；Quick Notes、来源添加不可用 | 固定与浮层使用同一内容模型，差异仅限必要布局；控制项有清楚状态 |
| 监控网页查阅 | 从时间线任意 URL 推导，最多取八条；并非已查阅页面记录 | 从明确的数据来源展示，避免把系统说明中的链接当成查阅历史 |
| 工作面空白页 | 入口图标本轮修正；部分副标题仍与参考不同 | 逐项核对图标轮廓、按钮比例和可执行快捷键，保留必要说明即可 |
| 文件页 | 搜索框约 36px，而本机 Qoder 约 28px；文件行约 30px，对照约 28px。工作区副标题行也略高；空态为普通文件符号 | 统一搜索、行高和工具栏密度；空态保留产品自己的图形，不复制对方品牌 |
| 文件树分隔条 | 视觉比例约 36% 文件树，但无障碍树报告默认值 50；源码缺少 `aria-valuenow/min/max` | 暴露真实比例与边界，键盘调整后数值同步 |
