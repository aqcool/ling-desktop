# LING 知识中心

知识中心是本机应用中的独立主页面。顶层只有「知识库」和「Repo Wiki」两个入口，沿用应用导航。聊天右侧的「项目知识」固定跟随当前工作区或 SSH 项目，只用于查阅。

## 知识库

一个知识库是一组主动整理的资料，不是记忆规则或代码索引的别名。

- 创建时填写名称，选择全部或指定工作区。全部范围包含当前 Profile 中现有及未来工作区；指定范围通过 Host 解析工作区或 SSH 项目的规范身份。可在库卡片或阅读页菜单中重命名、管理范围、删除。
- 库内提供资料目录、Markdown 阅读与编辑、正文目录、文档导出和整库导出。支持导入 512 KB 以内的 `.md`、`.markdown`、`.txt` 文件；单篇正文最多 128,000 字符。导入后先预览、编辑，再保存。
- 搜索只查当前库的资料，导出只包含明确选择的文档或库。资料不会自动成为 Agent 长期记忆。
- Agent 只检索当前项目可访问的资料库。改变生效范围不会复制、移动正文或改变版本；移除绑定后，原项目不能再检索或读取该资料。管理时通过库自身身份访问。
- 删除知识库会删除其中的资料及其版本和检索记录，不删除项目文件或原始会话。

## 项目 Wiki

先选择项目，再进入「Wiki 页面」「知识卡片」。Wiki 是面向开发者的阅读目录；知识卡片是供 Agent 按需检索的项目事实。两者同时生成，均附源码引用，不自动成为记忆规则。会话总结、记忆、代码查找与图谱收进「项目工具」菜单；个人记忆通过知识中心菜单管理。

任务监控顶部以卡片展示当前会话最近一次已确认总结及更新时间，点击进入完整总结。只按当前项目和会话读取，切换任务不沿用其他会话的摘要；没有总结时隐藏。查看卡片不创建整理任务或触发模型调用。自动总结仍由记忆设置独立控制，默认关闭。

Wiki 的阅读布局是页面目录、正文与本文目录。生成时先读取代码索引并规划最多两层的文档目录，再按概览、架构入口、开发流程和相关子系统组织页面，不把顶层文件夹直接当作文档目录。首次生成会建立代码索引。规划引用的文件必须真实存在；每篇正文基于带行号的原文生成。引用可点击查看代码，页面之间可以跳转。

Wiki 阅读区集中展示生成配置：中文/英文、自动更新、智能体引用。「设置 → 记忆」选择已有模型连接后才能生成 Wiki 或总结。Wiki 配置按项目保存；自动更新默认关闭，智能体引用默认开启。关闭引用后，Agent 工具不返回 Wiki 或知识卡片，用户仍可阅读。自动总结单独配置，默认关闭。不创建隐藏会话或使用另一套凭证。

手工记忆直接有效；总结提取的记忆需要确认。Wiki 手工编辑不会被后台覆盖；新的生成内容作为候选，确认时检查目标版本。内容支持归档和版本查看。

代码查找提供当前源码的字面搜索与结构索引检索。图谱的包含、相对导入来自 AST，虚线调用只表示语法候选。已配置 DSH LSP 时支持定义、引用、实现查询；远端路径不会发送给本机语言服务器。

## 本机存储与旧数据重置

数据保存于当前 Profile 的 `$DSH_HOME/ling-knowledge.sqlite`，使用 SQLite/WAL、事务、0600 权限与带版本的 schema。新版 schema 为 2。

按本次重做要求，schema 1 首次打开时会清空旧知识正文、版本、代码索引、设置与整理队列，再建立新结构；不迁移旧知识数据。后续打开 schema 2 不再清空。重置不触及 DSH 原始会话、项目源码、自动化数据或 SSH 连接配置。

每个项目以 Profile 身份、工作区 ID 和规范路径识别；SSH 项目以服务器 ID 和远端根目录识别。显示名不决定数据归属。资料库列表可以跨项目浏览，读取与检索验证生效范围，管理操作验证库的存储身份和版本。

DSH 自有的历史 FTS 数据库 `ling-session-search.sqlite` 与本模块独立，用于检索原始会话，不是旧知识库数据。

## 索引、Agent 与运行限制

- 复用 DSH 会话与模型服务；上游子模块保持不变。Renderer 只通过显式 Runtime/Remote 使用 Host 插件。
- Tree-sitter WASM 提供 TS/JS、Go、Python、Rust、Java 的结构解析；常见配置和文档参与文本检索。中文与代码标识符通过 SQLite FTS5 检索，独立检索器使用 reciprocal-rank fusion 合并结果。
- 本机索引监听源码变化；不支持递归监听时保留手动刷新。SSH 复用已有连接及文件 provider，外部修改手工刷新。依赖、构建产物、密钥和工作区外符号链接不参与索引。
- `knowledge_search`、`knowledge_read`、`code_relations`、`memory_remember` 每次确认当前项目范围。只将最多 8 条已确认记忆加入提示，其余资料按需读取。保存记忆需要最新用户消息明确要求记住。
- 会话总结读取原始已完成回合，保留失败和取消结果，不重复提取继承事件；支持持久化队列、取消和重试。
- 单文件 512 KB，索引最多 20,000 文件/128 MB，图谱最多 250 节点。Wiki 规划输入 64,000 字符，最多 16 页，每页最多 80 个文件/64,000 字符，每次页面生成返回正文与 1–4 张知识卡片，最多 6,000 输出 token。超过预算明确失败；已完成页面保留，并显示失败任务。
- 未引入 SaaS 服务、图数据库、向量服务、SCIP 导入或独立语言服务器。

## 验证

运行 `corepack pnpm check`。测试覆盖旧数据一次性重置、库与资料的归属、跨项目访问、库内搜索和导出、版本冲突、目录循环、Wiki 规划及源码引用、手工内容保护、取消恢复、本机/SSH 隔离，以及真实 Remote/Gateway 往返。无界面组件检查验证独立页面、目录阅读、源码跳转、创建和窄窗口布局。
